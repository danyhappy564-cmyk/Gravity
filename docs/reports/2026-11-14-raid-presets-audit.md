# 기본 레이드(스폰) 프리셋 6개 값 점검 (1.0.5 Task 7)

> 2026-11-14. 대상: 웹 `PRESETS`(index.html). 방법: 프리셋마다 설명 문장과 바꾸는 값을 기본값(`DEFAULTS.spawn`·맵 상한)과 견주고, 웹 견적 함수(`estimate`)를 테스트 샌드박스에서 돌려 레이드 전체 PMC·스캐브 수(최소–최대)를 붙였다. 서버는 호출하지 않았다.
> 판정 기준: ① 설명의 각 주장이 바뀐 값으로 뒷받침되는가 ② 서로 상쇄하는 값이 없는가 ③ 다른 설정이 덮어써서 효과가 사라지지 않는가.

**기본값:** 시작 PMC 35%, 웨이브 간격 6분, 웨이브 2–4명, 세기 초반 1.2·중반 1.0·후반 0.6, 시작 보호 90초, 위치 방식 혼합, 스캐브 첫 보충 4분, 근처 보충 끔, 보스 공통 확률 끔. 맵 상한(세관 24·공장 14·스트리트 30)은 공통 값을 따른다(`capOn:false`).

## 고친 것

1. **가볍게 — 맵 상한 줄이기가 적용되지 않음(기준 ③).** 프리셋이 `maps.<id>.cap`만 바꿨는데, 1.0부터 맵 값은 `maps.<id>.capOn`이 켜져야 쓰인다(웹 `capOf`, 서버 `ConfigModel` 같은 규칙). 그래서 실제 상한은 그대로였다. → 13개 맵에 `capOn:true`를 함께 넣는다. 결과: 세관 24→18, 공장 14→11, 스트리트 30→23.
2. **시작 스폰만 — 스캐브 웨이브가 그대로 남음(기준 ①).** 설명은 "웨이브 없이 시작 때만"인데 PMC 방식만 바꾸고 스캐브 방식(`scavStyle`)은 웨이브 그대로라 스캐브가 레이드 내내 73–105명 나왔다. → 13개 맵 `scavStyle:'start'`도 넣고 설명에 "(PMC·스캐브 모두)"를 붙였다. 결과: 세관 스캐브 3–5명.

테스트: `기본 레이드 프리셋 light 값: 맵 동시 상한이 실제로 줄어든다`, `기본 레이드 프리셋 startonly 값: PMC·스캐브 모두 시작 때만` — 고치기 전 FAIL, 고친 뒤 PASS.

## 사용자 확인 필요

- **시작 스폰만의 스캐브 수:** 고친 뒤 세관 기준 PMC 10명 + 스캐브 3–5명으로 매우 조용하다. 설명("조용한 레이드")과는 맞지만, 스캐브는 웨이브로 남기고 PMC만 시작 스폰으로 두는 쪽을 원하면 `scavStyle` 줄만 되돌리면 된다.
- **난전의 동시 상한:** 웨이브를 크게 해도 동시 상한(세관 24)은 그대로라 한 번에 보이는 봇 수는 기본과 같다. 상한까지 올릴지(프레임 부담)는 판단이 갈려 그대로 두었다.
