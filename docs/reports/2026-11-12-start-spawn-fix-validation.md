## 수정한 원인과 동작

1. **시작 스캐브 인원이0이 되는 문제:** 서버의 고정 n/n 웨이브가 게임의 AsOnline/Medium 인원 변환을 지나면서0이 됐습니다. Gravity 표식을 붙이고 변환 후 지정 인원을 복원합니다. 시작 인원은1명씩 나누어 전달합니다.
2. **다중 구역 이름 전달 문제:** 일반 스캐브 웨이브는 단일 구역 이름을 정확히 비교합니다. 쉼표 목록 대신 허용된 실제 구역 하나씩 순환 배정합니다. 구역 제외와 모두 끔의 기존 안전 처리를 유지합니다.
3. **시작 인원 분산:** 시작 스캐브를 첫 활동 구간에 흩뿌리던 계획을 지정 지연 시각의 시작 묶음으로 바꿨습니다. 지연0은 게임의 시작 전 준비 경로를 사용합니다. 시작 묶음과 후속 보충1명이 동시에 겹치는 것도 방지합니다.
4. **PMC 대원 지연:** 게임은 분대장 활성화 뒤 대원을 준비하며, 분대장 지점의 재사용 대기까지 검사합니다. 그 대기열은 레이드 시간이 흐르기 전에는 재시도하지 않습니다. 이미 상한·그룹·지점 선택을 통과한 시작 분대의 충분한 지점 목록에만 게임의 초기 대원 생성 경로를 적용했습니다. 새 좌표를 만들거나 분대 인원을 늘리지 않습니다. 대원 요청을 한 번만 실행하며, 중복 콜백이 진행 중인 예약을 해제하지 않게 했습니다.
5. **준비 대기와 시계:** 최대60초·120회·500ms 간격만 기다립니다. 취소·다른 레이드·상한 도달 등에서는 종료합니다. 로딩 대기로 후속 스폰이 앞당겨지지 않도록 네이티브 스폰 타이머를 보존하고 시작 이벤트에서 재개합니다. 강제로 EndTime만 바꾸지 않고 정렬 목록을 갱신하는 Restart를 사용합니다.
6. **타임라인 팝업:** 최소10·최대6 같은 역전 입력을 막고, 이미 저장된 역전 값의 예상 인원도 서버의 최대 올림 보정과 맞췄습니다. 생성된 팝업 입력으로 실제 apply를 실행하여 아래 카드 갱신도 검사했습니다.
7. **연구소 보호·버전:** 시작 인원 방식도 연구소 스캐브 허용 스위치를 따르게 했습니다. 서버·클라 프로토콜이 바뀌므로 둘 다1.1.x로 맞춰야 합니다. 구형1.0.x와의 혼합은 호환성 검사에서 거부합니다.
