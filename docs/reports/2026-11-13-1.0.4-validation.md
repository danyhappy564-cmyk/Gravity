## 반영한 내용

- 스폰 방식 변경 시 편집창이 클릭 위치를 따라 우하단으로 이동하던 문제를 수정했습니다. 처음 연 위치를 유지하고 화면 높이에 맞춰 내부에서 스크롤합니다.
- PMC·스캐브 편집창을 기본 수정/자세한 수정으로 통일했습니다. 숫자를 직접 입력할 수 있으며 최소·최대 범위를 검사합니다. 미리보기에서 기존 스폰 설정 카드를 그대로 사용하여 별도 설정 사본이 생기지 않게 했습니다.
- 맵 미리보기에는 해당 맵의 구역·보스·특수 봇·설치 팩션·변형 설정만 보여 줍니다. 연구소의 블랙 디비전·웨지는 별도로 보존하고 스캐브 허용이 꺼져 있으면 스캐브 바로가기를 숨깁니다. 전체 공통 설정은 모든 맵(공통)에서 필요한 분류를 눌러 엽니다.
- 공통 타임라인의 기본/자세한 수정은 같은 공통 설정 경로를 사용합니다. 맵 상세에서 공통 카드를 처음 바꾸면 그 카드만 맵별 값으로 전환합니다. 보스·특수 봇·팩션의 종류별 공통값은 창 안에 적용 범위를 안내합니다.
- 여러 맵 선택만으로 기존 값이 바뀌지 않습니다. 이후 변경한 항목과 맵별 전후 값을 표시합니다. 카드 첫 수정 시 그 카드의 나머지 공통값도 현재 값으로 고정된다는 점을 안내합니다. 전체 복사는 변경·유지 목록 검토 뒤 적용하며, 검토 중 값이 바뀌면 다시 검토합니다. 대상 맵의 두 배치 구역은 유지합니다.
- 기본 Realistic and Extended PMC Loadouts에 저장된 Realistic Live-like 1.0.2를 반영했습니다. 7티어·33개 표와 gear/roles/weapons/mods를 옮겼고 카드 이름·ID를 유지했습니다. JS의 실제 적용 함수에서 저장값·배열·가중치와 블랙리스트 보존을 확인했습니다. 기존 사용자 설정을 자동으로 이 프리셋으로 바꾸지는 않습니다.

## 실제 시험에서 추가로 발견한 문제

세관에서 PMC1·스캐브1·상한4·저격 끔으로 시작했을 때 스캐브2가 실제로 생성됐습니다. 시작 웨이브 전달 단계의 인원은1이었으나, 원본 맵의 marksman 최소2가 남아 있었습니다. 게임의 WavesSpawnScenario.CheckMinCounts는 해당 종류가 부족하면 다른 종류의 웨이브도 늘립니다.

Gravity가 관리하는 레이드 복제본에서 assault 최소값을0으로 하고, 저격을 끈 경우 marksman 최소값도0으로 하여 명시한 시작 웨이브가 증가하지 않게 했습니다. 최대값·다른 역할·클라 없는 세션·유지한 저격 최소값과 원본 목록은 보존합니다. 회귀 시험3개를 추가했고, 수정 전2실패/1통과에서 수정 후3통과를 확인했습니다. 수정본 실제 세관은 원시 웨이브1·생존 스캐브1로 일치했습니다.

## 확률 점검

- 실제 서버의 세관 최종 표에서 블러드하운드0·5·100%는 각각 같은 확률의 단일 항목으로 전달됐습니다.
- 실제 세관5% 레이드 내부 항목은 BossChance5, ShallSpawn=false, Activated=false, ForceSpawn=false, DependKarma=false, 빈 트리거로 확인했습니다. 해당 판은 등장하지 않는 판정이었습니다.
- 게임의 BossLocationSpawn.Init와 CalculateChance는 ShallSpawn에 확률 결과를 대입합니다. Init에서 결과가 재대입되는 경로가 있어 호출 횟수를 '한 번'으로 단정하지 않습니다. 성공 여부를 OR로 누적하는 코드는 아니며, ActivateWave는 ShallSpawn=false이면 생성 요청을 하지 않습니다.
- 서버 최종 처리 순서에서 블러드하운드·RUAF 순찰/검문소/사냥조·블랙 디비전 사냥조의0·5·100%를 각각100개 시드로 검사했습니다. 연구소 게이트는 서버에서 게이트별로 먼저 굴린 뒤 조건부 항목100%로 바뀌는 구조이며, 웨지와 정전 배율은 별도입니다. 기존 게이트0/100·배율 시험도 전체 시험에 포함됩니다.
- RUAF 순찰 수가 여러 개이면 무리마다 독립 확률입니다. 검문소·사냥조·연구소 게이트·웨지·다른 모드의 이벤트는 별도 경로입니다. 단일 슬라이더를 팩션 전체의 레이드당 확률로 해석하지 않도록 도움말을 보완했습니다. UNTAR는 현재 Gravity 관리 미지원입니다.
- 제보된 '4판 중3판' 빈도 문제는 이 환경에서 재현하지 못했습니다. 확률 로직은 근거 없이 바꾸지 않았으며, 제보자 환경의 동일 설정·모드 목록·실제 로그 대조는 미완료입니다. 단일 레이드와 코드 전달 시험으로 장기 빈도 전체를 보장하지 않습니다.
