# Gravity 1.0.6 구현 계획

> **실행 방식:** superpowers:executing-plans — Claude가 직접 구현한다(하위 에이전트는 사용자 허락 뒤에만, Sonnet). Codex는 2026-11-14부터 사용 중지 → 검토 단계는 Claude 자체 검토. 단계는 체크박스로 추적한다.

**목표:** Forge·외부 사용자 제보 3건(#39 원래 없는 맵의 특수 봇, #42 스캐브 역방향 웨이브·특수 무리 웨이브·레버 무리, 타임라인 특수 봇 표시)을 한 번에 1.0.6으로 낸다. 1.0.7로 따로 내려던 스캐브 곡선도 포함(사용자 2026-11-14).

**구조:** 서버 `src/Gravity.Server`(SPT 4.1 C#), 공용 `src/Gravity.Shared`(서버·클라 공통 순수 계산), 클라 `src/Gravity.Client`(BepInEx), 웹 한 파일 `src/Gravity.Server/wwwroot/index.html`. 웹 설정 경로 → `ConfigModel`이 읽음 → `GravityRuntime.BuildRaid`가 판 복제본에 순서대로 적용: `RaidSpawnApplier.Apply`(PMC·스캐브) → `FactionRaid.Apply`(RUAF·BlackDiv, 연구소 게이트) → `RaidSpawnApplier.ApplyBosses`(보스·특수 봇) → `EventRaid` → `CapApplier`.

**기술:** .NET(xUnit `tests/Gravity.Tests`), Node 내장 test(`tests/web/ux.test.cjs`).

## 확인해 둔 사실 (2026-11-14, 코드·SPT 원본 데이터)

- 특수 봇 4종(레이더 pmcBot·로그 exUsec·컬티스트 sectantPriest·블러드하운드 arenaFighterEvent)은 맵에 원래 항목이 없으면 설정을 버린다. 레이더·로그 추가 스폰 `AddExtraSpecials`(`own.Count==0` → 건너뜀), 컬티스트·블러드하운드는 `ApplyBosses`가 원래 항목만 고침. 웹은 모든 맵 슬라이더를 보여 준다.
- 원래 항목(SPT server-csharp main 데이터): 연구소 레이더 16개 = 시각 무리 2(60% 300초 2층, 60% 900초 1층) + 탈출구 트리거 14(35~45%, Gate1/Gate2는 Delay 8). 리저브 4개 = 시각 1(40% 1470초 철도 창고) + 트리거 3(D2 레버·탈출구 632·`raider_simple_patroling` Time 3). 등대 로그 8개는 전부 판 시작(트리거 없음). 컬티스트·블러드하운드도 트리거 없음. → **트리거 무리는 연구소·리저브 레이더뿐.** 설치본 4.1과 숫자가 다를 수 있어 서버가 실제 값을 읽어 웹에 보낸다.
- 트리거 무리 역할 바꾸기는 이미 쓰는 방식이다: `FactionRaid.ApplyLab`이 게이트 트리거 항목을 `v with { BossName = blackDivAssault … }`로 바꿔 넣는다(트리거 유지). 같은 방식으로 다른 역할로 바꿀 수 있다(코드상 가능, 다른 역할의 두뇌가 그 구역에서 제대로 움직이는지는 인게임 확인).
- **BlackDiv·Blackout 연동:** 탈출구 열 때 나오는 BlackDiv는 BlackDiv 모드가 게이트 트리거(`autoId_00632_EXFIL`=Gate1, `autoId_00014_EXFIL`=Gate2)의 레이더 항목을 차지해서 생긴다. Blackout 모드는 다음 연구소 판의 정전 여부만 정한다(`BlackoutStateRouter.CurrentRaidBlackout`). Gravity는 BlackDiv "관리" 때 게이트 확률(`labsGate`)·정전 연동(`blackoutLink` always/only/boost)을 이미 처리하고, 이것이 `ApplyBosses`보다 먼저 돈다. → 새 레버 무리 조절은 **그 뒤에 남은 pmcBot 트리거 항목에만** 건다. BlackDiv로 바뀐 게이트 항목은 건드리지 않는다.
- 타임라인 특수 봇 줄은 서버 `MapMeta.Roster`(역할 → 최대 확률)만 받아 줄마다 ✦ 하나를 설정 시각(원래 시각이면 0분)에 그린다. 그래서 연구소 5·15분 무리·레버 무리가 안 보이고 0분에 별이 찍힌다.
- PMC는 시간대별 강도(초반·중반·후반, 기본 1.2·1·0.6, `SpawnPlanner.IntensityAt`)가 있고, 스캐브는 활동/휴식 창 + 고정 상한(`ScavSchedule` softCap·보충 간격)뿐이다. RUAF 순찰은 등장 시각 범위 안에서 고르게 뽑는다. UNTAR는 감지만 하고 관리하지 않는다(봇 이름 미확인).

## 정한 기본값 (사용자가 바꾸라고 하면 바꿈)

1. 레버 무리 확률은 **맵별 칸**(비우면 원래 확률), 인원은 범위(0~0 = 원래). 배수 방식은 쓰지 않는다(맵마다 원래 확률이 달라 결과를 예측하기 어려움).
2. 레버 무리 역할: 레이더(기본) / 로그 / BlackDiv 사냥조(BlackDiv 설치 시). 게이트 BlackDiv 설정과 겹치면 게이트 쪽이 먼저.
3. 스캐브 곡선은 **살아 있는 스캐브 상한과 보충 속도 둘 다**에 같은 배수를 건다. 맵 동시 상한은 넘지 않는다.
4. 추가 무리 수 기본 1(지금과 같음).
5. 제외: BlackDiv 사냥조·웨지, 한 번만 나오는 무리(RUAF 사냥조·검문소, 컬티스트·블러드하운드 곡선). UNTAR 관리는 이번에 안 함.
6. "지원 정보 복사" 버튼은 뺀다(사용자: 자세한 진단 보내기가 이미 있음).
