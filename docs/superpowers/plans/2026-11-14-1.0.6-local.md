# Gravity 1.0.6 로컬 시험·보완·빌드·배포 계획 (사용자 PC)

> **로컬 세션용.** 클라우드에서 코드·단위 시험·웹 시험까지 끝낸 1.0.6을 집 PC에서 실제 게임으로 시험(SlopBridge 사용, 사용자 11-14 승인)하고, 고칠 것을 고친 뒤 Release 빌드·zip까지 만든다. 태그 푸시·업로드·Forge 게시는 사용자가 한다.

**시작할 때 붙여 넣을 말(새 로컬 채팅):**
`Gravity 1.0.6 로컬 시험 시작 — Gravity docs/superpowers/plans/2026-11-14-1.0.6-local.md 대로. SlopBridge 설치·서버/게임 직접 실행·프로필 백업 후 시험·끝나면 원복까지 승인.`

**권장:** Opus · 노력 high(실제 판 판단·버그 수정·클라 빌드 오류 대응). 토큰 약 50~80만, 시간 6~8시간(필수 판 10개 + 웹 + 수정 1~2회, 하루에 못 끝내면 이틀로 나눔).

**근거 문서:** 검증 보고서 `docs/reports/2026-11-14-1.0.6-validation.md`(커밋 표·"남은 것"), 계획 `2026-11-14-1.0.6.md`(1·2차)·`2026-11-14-scav-wave-list.md`(3차: 웨이브 목록·티어 분포·주간 보스·봇 체력/스킬), KB `tools/spt-ingame-sim/README.md`(SlopBridge 절)·`tools/spt-ingame-check/README.md`.

## 지킬 규칙 (전부 PROJECT-RULES·LOCAL-WINDOWS 그대로)

- 게임·서버를 **끈 상태에서만** 설치·교체. 바꾸는 파일만 백업 → 복사 → **파일별 해시 확인**. 프로필(`SPT_Runtime\user\profiles\*.json`)은 시험 전 백업, 끝나면 복원·해시 확인.
- SlopBridge는 이번 시험에만 넣고 끝나면 `bridge-kit.ps1 remove`. 숨긴 모드(`probe-env.ps1 set -Hide`)는 `restore`로 되돌린다.
- 증거(스크린샷·로그·jsonl)는 `F:\코딩\Index\클로드방\gravity106-check-20261114-v001\`(날짜·번호는 실제 날짜로). 판마다 하위 폴더 `01-wavelist\` 식.
- 사용자가 PC를 쓰는 중이면 마우스를 뺏기 전에 알린다.
- 버그를 고치기 전 `bash tools/pastcheck.sh Gravity <키워드>`, 고칠 때는 실패하는 시험 먼저(클라 코드는 공용 순수 로직으로 빼서 시험할 수 있으면 그렇게).
- 커밋 작성자 R_F, main 직푸시, Claude 트레일러 없음. 방명록엔 실제 모델.
- **문구 규칙(사용자 11-14):** 버튼·설명·노트에 "APBS처럼" 같은 다른 모드 비교 문구를 쓰지 않는다.
- 노트(릴리즈 노트)는 **묻기 전에 쓰지 않는다**(R-1). 끝나면 "릴리즈 노트 4종 만들까요?"만 묻는다.

## 1단계: 빌드·자동 시험 (20분)

1. `dotnet build Gravity.sln -c Release`(TarkovDir 기본 `E:\SPT 4.1\`). **목표: 경고 0·오류 0.** 클라는 클라우드에서 처음 빌드되는 코드가 있다:

2. `dotnet test tests/Gravity.Tests -c Release` → **586/586**. 한국어 로그 문구를 확인하는 시험이 있어, 영어 로캘이면 10개 남짓이 문구 차이로 실패할 수 있다(코드 문제 아님 — 실패 목록이 전부 문구 비교인지 확인).

4. Build 폴더 구조 확인: `Build\BepInEx\plugins\Gravity\`(클라 dll), `Build\SPT_Runtime\user\mods\Gravity\`(서버 dll·wwwroot·presets). 1.0.5 zip(`F:\코딩\Index\빌드됨\Gravity-1.0.5\Gravity-1.0.5.zip`) 파일 목록과 비교해 빠지거나 새로 생긴 파일을 적는다.

## 2단계: 설치 (15분)

1. 게임·서버 꺼짐 확인(`check.ps1 status`).
2. 백업 `F:\코딩\Index\install\Gravity-1.0.6-<날짜>-v001\`: 지금 게임의 `BepInEx\plugins\Gravity\`, `SPT_Runtime\user\mods\Gravity\`(**`config\gravity.json`·`presets.json` 포함**), `user\profiles\*.json`.
3. Build 내용을 게임 폴더로 복사(사용자 `config\`는 덮지 않음) → 파일별 SHA256 비교.
4. SlopBridge: `pwsh -File tools/spt-ingame-sim/bridge-kit.ps1 install` → `status`.
5. `probe-env.ps1 start`(서버 → 브릿지 → 게임, 메뉴까지). 서버 로그에서 확인:

   - **주간 보스 줄**: `이번 주 보스 <역할> · <맵> — Gravity 주간 보스 켜짐(100%)`(SPT 주간 보스가 꺼져 있으면 줄 없음 — 그것도 기록)
   - 클라 BepInEx 로그 `LogOutput.log`: Gravity 클라 1.0.6, 버전 일치

## 3단계: 실제 판·웹 — **시험 범위 = `docs/reports/2026-11-14-1.0.6-test-matrix.md` 전체** (1.0.5 → 1.0.6 모든 변경, 항목 약 100개)

- 범위: 공통 회귀(R) · 원래 없는 맵 특수 봇(S) · 트리거 스폰 조절(G) · 추가 무리(X) · RUAF 곡선·팩션 표시(F) · 스캐브 강도(C) · 스캐브 웨이브 목록(W) · 티어 분포(D) · 주간 보스(B) · 봇 체력·스킬(H) · 상한 팁·웹 기타(U) · 같이 쓰는 모드(M).
- 진행: 표 아래 **"판 묶음" P1~P11 + 웹 + 시작·끝** 순서로. 필수 항목만 = 판 10개 + 웹(약 5~6시간) → 하루에 다 못 하면 P1·P2·P5·P9·웹 먼저, 나머지는 다음 날(`inbox.py note`로 어디까지 했는지).
- 판마다 그 판의 항목 ID 결과를 시험 범위 문서 맨 아래 "결과" 표에 바로 적는다(통과/실패/기록 + 증거 폴더 + 고친 커밋).
- 설정은 웹(크롬, `https://127.0.0.1:6969/gravity/` — 자체 서명 인증서라 크롬 화면 캡처·클릭으로)에서 바꾸고 저장하거나, 서버를 끈 상태에서 `config\gravity.json`을 직접 고친다(경로는 웹 `data-p` 이름 그대로). 레이드 시작·무적·봇 읽기는 브릿지(`probe-raid.ps1`, `probe-lib.ps1`). **진단 로그 "자세히"·봇 장비 기록 켜고** 시작, 판마다 `LogOutput.log`·서버 로그·리포트(`config\reports\`)를 증거 폴더(`<ID>\`)에 복사.
- R4(옛 클라 섞임)는 1.0.5 zip의 클라 DLL을 잠깐 넣는 판이라 마지막에 하고, 끝나면 1.0.6 DLL로 되돌리고 해시 확인.
- 필수 항목이 하나라도 실패하면 4단계(수정)로 가고, 고친 뒤 그 판 묶음만 다시 한다. 선택 항목 실패는 "알려진 점"으로 적고 사용자에게 1.0.6에 넣을지 묻는다.

**봇 값 읽기(브릿지):** `gameWorld` → `AllAlivePlayersList` → `collection` → 각 봇 `Profile.Info.Settings.Role`, `ActiveHealthController`의 부위별 체력(`GetBodyPartHealth`), `Skills`(근력·지구력 레벨). 정확한 멤버 이름은 `members`(query)로 찾는다(kb README "게임 안 값 읽기"). 핸들은 금방 사라지니 한 묶음에서 읽는다.

## 4단계: 수정·보완 (발견 시)

1. 문제마다: 증거(로그 줄·스크린샷) → 최근 바뀐 것부터(`git log v1.0.5..HEAD`, 방명록 search Gravity) → 원인.
2. 서버·공용 코드는 실패 시험 먼저 → 고침 → `dotnet test` 전체. 웹은 `ux.test.cjs`에 시험 추가.
3. 클라 DLL은 게임 재시작이 필요 → **고칠 것을 모아서** 한 번에 빌드·설치(바뀐 파일만, 해시)·재시작 → 그 판만 다시.
4. 커밋 메시지 `fix(...)`, 보고서 "로컬 실제 판" 절에 판·결과·커밋을 적는다.
5. 바로 못 고치는 것은 INBOX에 `inbox.py add Gravity 확인 "..."`로 남기고 사용자에게 1.0.6에 넣을지 묻는다.

## 5단계: 원복 (15분)

1. `probe-env.ps1 stop`(게임 → 서버 → 브릿지).
2. `bridge-kit.ps1 remove`, `probe-env.ps1 restore`(숨긴 모드·프로필). 프로필·`config\gravity.json` 해시가 백업과 같은지 확인(시험 설정이 남지 않게 — 사용자 원래 설정으로).
3. 게임에는 **최종 1.0.6 Build 파일만** 남기고 해시 확인.

## 6단계: 빌드·배포 준비 (20분)

1. 버전 확인: `GravityVersion.Current`·`ModMetadata.Version`·클라 플러그인 = 1.0.6, 웹 상단 1.0.6.
2. 기본값 확인: 진단 로그 기본 "요약", 봇 장비 기록 끔, 새 칸 전부 기본(= 1.0.5 결과).
3. `dotnet build Gravity.sln -c Release` 경고 0·오류 0, 시험 전부 통과(마지막 커밋에서 다시).
4. zip: Build 폴더 구조 그대로(`BepInEx\plugins\Gravity\…` + `SPT_Runtime\user\mods\Gravity\…`, 사용자 `config\` 제외) → `F:\코딩\Index\빌드됨\Gravity-1.0.6\Gravity-1.0.6.zip`, SHA256 기록. 1.0.5 zip 목록과 비교해 새 파일 설명.
5. 문서: 보고서 마무리(로컬 판 결과·zip 해시), README 한/영 1.0.6 문단 최종 확인, 소개 사이트(`site/index.html`·`site/arca/index.html`)에 웨이브 목록·티어 분포·봇 체력/스킬 한 줄씩(사이트가 그 기능을 다루는 경우), `changelog.py add`.
6. KB: NOTES 상태 절 덮어쓰기, INBOX #43·#44·#46 `done`, 방명록(실제 모델), 푸시.
7. 사용자에게: 커밋 해시·zip 경로·SHA256·판 결과 요약 + **"릴리즈 노트 4종(GitHub·아카라이브·디스코드·Forge) 만들까요?"** 질문만. 노트는 답을 받은 뒤(`docs/RELEASE-NOTES.md`, 변경점은 GitHub v1.0.5 대비 전부, 아카 닉언·이모티콘 금지, `^^7` 끝, 오리지널 모드라 후원 링크, Forge 노트엔 후원 없음).
8. Forge 답글 초안(#1 주간 보스 고침, #2 봇 체력·스킬 티어별 페이지, 웨이브 목록 제안자, 티어 분포 제안자) — 비교 문구 없이 영어, 사용자가 게시.

## 중단·되돌리기
