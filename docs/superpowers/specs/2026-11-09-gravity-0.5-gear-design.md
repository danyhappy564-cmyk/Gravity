# Gravity 0.5 장비 모듈 설계

> 원래 로드맵 0.5 = 장비. 참고 모드(APBS)는 원리만 봤고 코드·데이터·문구는 가져오지 않았습니다.
> APBS가 있으면 장비 모듈은 잠깁니다(둘이 같은 봇 장비를 서로 덮어씀). 인게임 확인 때만 APBS를 잠깐 뺍니다.

## 1. 끼우는 자리

SPT가 봇 하나를 만들 때 그 봇 종류 자료(`BotType`)를 **봇마다 복제**한 뒤 `BotEquipmentFilterService.FilterBotEquipment`로 레벨별 필터를 겁니다.
Gravity는 이 함수 **바로 뒤(Postfix)**에서 같은 복제본을 고칩니다. 원본 DB는 건드리지 않으므로 끄면 즉시 SPT 기본으로 돌아갑니다.

| 패치 | 하는 일 |
|---|---|
| `BotLevelGenerator.GenerateBotLevel` 뒤 | PMC 레벨을 웹 "봇 레벨 기준"(내 레벨 ± 티어별 폭 / 고정 / 단순 폭)으로 다시 뽑음 |
| `BotEquipmentFilterService.FilterBotEquipment` 뒤 | 티어 결정 → 장비·탄약·부품 목록 걸러내기·무게 조정 → 확률·개수 표 적용 |
| `BotEquipmentModGenerator.FilterPlateModsForSlotByLevel` 앞 | Gravity가 입히는 봇이면 SPT의 레벨별 방탄판 무게 대신 이미 걸러 둔 판 목록을 그대로 씀 |
| `BotGenerator.GenerateBot` 앞·뒤 | 앞: 이전 봇 상태 지우기. 뒤: 무기·방탄 내구도를 티어 범위로 |

## 2. 티어 정하기 (웹 `tierDist`와 같은 규칙)

1. 봇 역할 → 웹 봇 id(usec·bear·scav·marksman·boss_*·f_*·cultist·raider·rogue·bloodhound·infected·ruaf·blackdiv·wedge). 모르는 역할·`roles.<id>.on` 꺼짐 → 손대지 않음(SPT 기본).
2. `roles.<id>.mode` = fixed → 그 티어. follow·offset → `gear.tierMode`:
   - fixed: `gear.fixedTier`.
   - level: 가상 레벨 L(PMC는 실제 레벨)을 `lvRange(내 레벨)`에서 고르고 L이 속한 티어.
   - mixed: 위 티어에서 섞기 표(`gear.lv.weights`) 비율로 위아래 티어.
   - offset이면 ±`roles.<id>.offset`. 마지막에 `gear.startTier` 아래로는 안 내려감.
3. 빈곤 확률(`roles.<id>.poverty`)에 걸리면 두 티어 내림.

## 3. 목록 고치기 (봇마다 복제본에서)

- **아이템 티어(자동)**: 장비 칸별로 모든 봇 목록에 나오는 아이템을 가격(시세, 없으면 핸드북) 순으로 7등분. 탄약은 관통력을 티어별 관통 상한에 맞춰 티어를 매김.
- **무게**: 봇 티어 e, 아이템 티어 t: t > e면 뺌, 아니면 원래 무게 × max(2, 30 − 6(e − t)) / 30(웹 티어 편집기 기본 표와 같은 식). 다 빠지면 가장 낮은 티어 아이템을 남김.
- **상한**: 탄약 관통 ≤ 티어 `pen`(스캐브 묶음은 블랙리스트 `scavPenCap`도), 헬멧·조끼 자체 등급 ≤ `fMax`, 앞·뒤판 등급 `fMin~fMax`, 옆판 ≤ `side`.
- **빼기**: 블랙리스트(봇 묶음별), 퀘스트 아이템(`gear.noQuest`·`blacklist.blockQuest`), 열화상(`thermalsT7`이면 T7만, 밤에는 `weapons.night.thermal` 확률), 원거리 조준경(`longScope` 확률에 안 걸리면 배율 조준경 뺌), 모드 아이템(이번 판 묶음 밖·`pmcOnly`).
- **모드 아이템**: SPT 원본 `items.json`에 없는 아이템. `mods.subset`이면 판마다 무기 N·장비 N·부품 N개만 고름(같은 판 봇은 같은 묶음 → 클라가 불러올 모델 수 감소). `mods.mult`는 모드 아이템 무게 배율.

## 4. 확률·개수

- 장비 칸 확률·무기 부품 확률·개수(탄창·의약품·주사기·수류탄·음식·음료·전리품)는 티어 편집기 "개수·확률" 표(`tierData.<묶음 또는 봇>.<티어>.chance/mods/gen`)를 씀. 표가 없으면 웹 기본식과 같은 값.
- 티어 상한(`mags`·`meds`·`nades`)이 개수의 최대값을 자름. `helmetAcc` → 헬멧 부속 확률. 방탄판 확률은 봇별(`frontPlate`·`sidePlate`).
- 무기 구성: 개머리판·더스트커버·조준경 항상(100%), 머즐 강제. 밤 레이드: 야투경 확률.
- `roles.<id>.loot` 꺼짐 → 가방·주머니·리그 전리품 0.

## 5. 내구도

무기 `wMin~wMax`, 방탄(조끼·헬멧·판) `aMin~aMax`. 봇별 범위(`roles.<id>.wDur*`·`aDur*`)와 겹치는 구간을 쓰고, 안 겹치면 티어 범위.

## 6. 이번 판에 하지 않는 것(다음 판)

| 칸 | 이유 |
|---|---|
| 티어 편집기의 아이템별 무게 표(무기·방어구·탄약·의약품·외형) | 웹 표가 예시 아이템이라 실제 아이템 목록 연결이 먼저 필요 → 0.5.x |
| 상탄/하탄 분리, 탄창 상탄 | SPT 탄약 생성 안쪽을 바꿔야 함 |
| 낱개 탄약·대용량 탄창·조준경/전술 장치 개수 제한 | SPT 설정이 역할 단위라 봇마다 못 바꿈 |
| 맵별 무기 성향, 손전등 켜기 | 무기 분류·클라 쪽 필요 |
| 뒤판은 앞판 따라가기·옆판 등급 앞판 이하 | 판 생성 순서 안쪽 |
| 열쇠·퀘스트 템·의약품 남은 양·다시 굴리기·귀중품·키카드 | 전리품 생성 안쪽 |
| 모드별 허용(모드 이름 단위), 옷 묶음 | 아이템이 어느 모드에서 왔는지 알 길이 없음 |
| 플레이어 스캐브 장비 | SPT가 필터를 건너뜀 |

## 7. 판정(검토 필요)

- 43. 아이템 티어는 가격 7등분(칸별, 모든 봇 목록 합집합 기준). 모드 아이템도 같은 식이라 가격을 이상하게 매긴 모드는 티어가 틀릴 수 있음.
- 44. 티어 상한(`mags` 등)과 편집기 개수 표가 겹치면 작은 쪽.
- 45. 봇별 내구도와 티어 내구도는 겹치는 구간, 안 겹치면 티어.
- 46. 스캐브·보스 등 PMC가 아닌 봇의 실제 레벨은 바꾸지 않음(SPT도 1로 둠). 티어용 가상 레벨만 뽑음.
- 47. `weapons.muzzle.chance`는 티어 표의 머즐 확률과 겹쳐 쓰지 않음(강제만 적용).
- 48. "열화상" = 열화상 고글(T-7 분류) + 특수 조준경 중 이름이 열화상인 것(REAP-IR·FLIR·T12·ZEUS·Ultima·Shakhin·Echo1 thermal 등). 야간 조준경·일반 야투경은 열화상 아님(Codex 6번 반영). SPT 데이터에 열화상 표시 칸이 없어 이름으로 가름 → 이름에 thermal이 없는 모드 열화상은 못 가림. 조준경 칸과 야투경 칸 둘 다에서 뺌. 웹 기본 블랙리스트의 예시 id(m995·t7·labcard_red)는 실제 id로 바꿈.
- 49. 판마다 모드 아이템 묶음은 스폰 모듈과 따로 정함(ABPS로 스폰이 잠긴 판에도).
- 50. 막힌 아이템(블랙리스트·퀘스트·묶음 밖 모드)은 빈 목록을 메울 때도 되살리지 않음. 예외: 주무기 칸(맨손 봇 방지)과 탄약(칼리버마다 하나).
- 51. 부품 칸이 다 빠지면 막히지 않은 것 중 방탄판은 가장 가까운 등급, 조준경·야투경은 열화상이 아닌 것만 되살림. 없으면 칸을 비움.
- 52. SPT가 나중에 새로 만드는 목록도 같은 기준으로 거름: 무작위 부품 칸(동적 목록), 무작위 방어구 칸 부품, 방탄판 선택, 역할별 전리품 캐시(보안 컨테이너 제외), 개수 표의 고정 목록. Unheard PMC 주머니 보정 뒤에도 전리품 끄기 유지.
- 53. 모드 아이템 등장 배율은 장비 칸과 탄약 무게에만 곱함(웹 안내도 그렇게 바꿈).
