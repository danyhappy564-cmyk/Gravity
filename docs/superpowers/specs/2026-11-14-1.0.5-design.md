# Gravity 1.0.5 설계 — 언어 저장·프리셋 이름·보스 맵별 확률·의상 탭

> 2026-11-14. 근거: 외부 사용자 피드백 3건(KB INBOX #32~#34)과 사용자 추가 요청.
> 1.0.4 빌드·검증은 Codex가 했다 — 절차·증거는 `docs/reports/2026-11-13-1.0.4-validation.md`를 **참고만** 한다.

## 1. 웹 언어 저장 (INBOX #32)

- **문제:** `wwwroot/index.html` 501줄 `lang='ko'` 고정. 언어 선택을 저장하지 않아 서버 재시작·새 탭마다 한국어.
- **고침:** 언어 버튼을 누르면 `writeLocal('gravity.lang', lang)`. 시작 때 `readLocal('gravity.lang')`, 없으면 `navigator.language`가 `ko`로 시작할 때만 `ko`, 아니면 `en`.
- 홈페이지(`site/`)는 이번 범위 밖.

## 2. 프리셋 이름이 한국어로만 나오는 문제 (사용자 추가 요청)

- **문제:** 새 프리셋 이름을 만들 때 그 순간 언어로 글자를 굳혀 저장한다(`customName` 2135줄 `커스텀 프리셋 N`, 2354줄 `내 레이드 N`, `… 사본`). 1번 문제 때문에 늘 한국어로 굳는다.
- **고침:** 자동 이름은 화면에 그릴 때 현재 언어로 바꿔 보인다(`커스텀 프리셋 N`↔`Custom preset N`, `내 레이드 N`↔`My raid N`, 끝의 ` 사본`↔` copy`). 사용자가 직접 지은 이름은 그대로. 저장 형식은 바꾸지 않는다(옛 파일 호환).
- **"커스텀 프리셋 1~6":** 배포 zip·웹 코드 어디에도 미리 만드는 부분이 없다(새로 깔면 0개). 기본 제공 프리셋을 고치면 `presetTouched`/`markEdited`가 "커스텀 프리셋 N"을 자동으로 만든다 — 사용자가 테스트 중 만든 것으로 결론(사용자 11-14 "내가 잘못 만든 거일 수도"). 코드 변경 없음. 사용자 PC `config/presets.json`의 장비 `커스텀 프리셋 1`은 사용자가 지우라고 할 때만 백업 후 삭제.

## 3. 보스 맵별 등장 확률 (INBOX #34)

- **현재:** `BossSettings.Chance` 하나 + `Maps`(맵 켜고 끄기). 특수 봇은 이미 맵별 `Chance` 사전.
- **설정:** `bosses.<id>.mapChance.<map>` (0~100). 없는 맵 = 보스 기본 확률.
- **우선순위(사용자 승인 11-14):** 맵별 값 > 보스 공통 확률(`bossCommon`) > 보스 기본 확률. 즈랴치 공통 제외 규칙은 그대로.
- **바꿀 곳:** `ConfigModel.cs`(BossSettings에 `MapChance` 추가·읽기), `RaidSpawnApplier.ApplyBosses` 138·178줄(확률 계산을 한 함수로), 웹 `bossChance(b)`→`bossChance(b, mapId)`, 보스 상세 "나오는 맵" 아래 맵별 확률 칸(비우면 기본), 미리보기·시뮬 표.
- 점증·점감(`bossProg`)·주간 보스는 지금 동작 그대로 두고, 맵별 값 위에 적용되는지만 테스트로 고정.

## 4. 의상 탭 (INBOX #33, 사용자 결정 11-14)

- **범위:** "모드 아이템" 페이지에 **의상** 탭을 추가한다. 기존 무기·장구류·부착물·기타 탭처럼 **모드 단위 체크만** — 옷 하나하나 고르는 기능은 만들지 않는다.
- **목록:** SPT 원본 `database/templates/customization.json`에 없는 `Body`·`Feet` 외형을 모드 것으로 보고, 기존 `GearItemSource.Scan`으로 어느 모드 것인지 찾는다. 탭에는 모드 이름과 옷 개수.
- **적용:** 봇 생성 때(`GearApply.Apply`) 봇 외형 칸 `body`·`feet`를
  - 바닐라 항목은 그대로,
  - 허용한 모드의 옷은 진영(`Side`: Usec→usec, Bear→bear, Savage→스캐브)에 맞는 봇에 추가(무게 = 그 칸 바닐라 평균 × 모드 아이템 등장 배율),
  - 허용 안 한 모드의 옷은 뺀다(다른 모드가 봇에 넣었어도).
  - 보스·호위·특수 봇은 건드리지 않는다. 장비 모듈이 꺼졌거나 잠겼으면(APBS 등) 아무것도 안 한다. 뺀 뒤 칸이 비면 원래대로 둔다.
- 기존 웹의 `mods.clothing`(부위별 일부만 사용) 슬라이더는 서버 구현이 없다 — 이번에 레이드별 일부 사용에 연결하거나, 연결하지 않으면 화면에서 숨긴다(빌더 판단, 결과를 보고).
- 시험 재료: 설치된 `AllTheClothes`·`WTT-Artem`·`Russian-SF-Pack`.

## 4-1. 기본 제공 레이드(스폰) 프리셋 값 점검 (사용자 추가 요청 11-14)

- 대상: 웹 `PRESETS`(index.html 720줄) 6개 — 기본·본섭 느낌·난전·무한 리필·시작 스폰만·가볍게.
- 방법: 각 프리셋 설명(desc)과 실제 값이 맞는지, 기본값(`DEFAULTS.spawn`·맵 `cap`)과 견줘 표로 정리 → 설명과 어긋나거나 효과가 거의 없는 값을 고친다. 고친 값은 근거와 함께 보고서에 남긴다.
- 확인: 웹 미리보기(시간대별 봇 수) 전/후 비교, 웹 테스트로 프리셋 패치 값 고정.

## 4-2. 기본 장비 프리셋에서 PMC가 방탄판·헤드셋 없이 나오는 문제 (외부 피드백 11-14)

- **조사 결과(11-14):** "Gravity 자동" 표 T1 확률이 SPT 원본 PMC보다 훨씬 낮다.
  | 항목 | Gravity 자동 T1→T7 | SPT 원본 usec/bear |
  |---|---|---|
  | 방탄복(ArmorVest) | 40→95 | 75 |
  | 헤드셋(Earpiece) | 15→85 | 50 |
  | 방탄 리그 | 10→60 | — |
  | 앞·뒤판(PMC) | 90 | 100 |
  PMC는 `follow`(플레이어 레벨을 따라감)라 저레벨 플레이어는 T1~T2 PMC를 주로 만난다 → 방탄복 없는 PMC 60%, 헤드셋 없는 PMC 85%.
- 방탄판 등급 상한(T1 앞뒤 2~3급, 옆 1~2급)도 판을 빼는 원인 후보: `GearApply.FilterCore`가 등급 밖 판을 빼고, 남는 판이 없으면 원래 목록으로 되돌리지만 무게 0인 판뿐이면 빈칸으로 둔다(`ok.Count == 0`).
- **고침(사용자 승인 11-14 "원본 수준으로 올림"):** PMC 표의 하한을 SPT 원본 수준으로 — 방탄복 T1 75(T7 95 유지), 헤드셋 T1 50(T7 85 유지), PMC 앞·뒤판 100. 스캐브·보스 표는 그대로. 기존 사용자의 저장된 장비 표(편집한 커스텀 프리셋)는 건드리지 않고, "Gravity 자동" 기본값만 바뀐다. 방탄복을 입었는데 판이 빈 경우가 등급 상한 때문인지 봇 기록으로 확인하고, 맞으면 "칸이 비면 등급 상한을 한 단계씩 넓혀 채운다"로 고친다.
- 확인: 실제 레이드 봇 기록에서 T1·T4 PMC의 방탄복·판·헤드셋 착용률 전/후.

## Approaches (고른 것)

- 보스 확률: (가) 맵별 덮어쓰기 칸 — **채택**, 기본 확률 하나로 쓰던 사용자는 그대로. (나) 특수 봇처럼 맵별 표로 완전히 교체 — 단순 사용자에게 칸이 너무 많아 제외.
