# Gravity 0.3 설계: 보스 세부·특수 봇·보고 보강

> **상태: 초안, 사용자 미승인.** 사용자 11-09 "인게임 확인하고 0.3 ~> 1.0 까지 쭉 진행해"에 따라 Claude가 범위를 정했습니다. 사용자 결정이 필요한 곳은 **[검토 필요]**로 표시했습니다(1.0 때 한 번에 검토).
> 0.2 설계 `2026-11-09-gravity-0.2-client-design.md`의 제약(클린룸, ORBIT 호환, ABPS 잠금, 커스텀 맵 손대지 않기, 한국어·이모지 금지)을 그대로 따릅니다.

## 1. 목표와 범위

0.2까지 보스는 켜기·확률·맵만 적용됩니다. 0.3은 웹의 보스·특수 봇 칸을 실제 레이드에 반영하고, 0.2 인게임에서 판단을 미룬 것(스캐브 밀도, 연구소 무한 PMC)에 근거와 동작을 더합니다.

| 번호 | 기능 | 어디서 |
|---|---|---|
| G1 | 보스 세부: 호위 수, 등장 시간, 난이도, 호위 데려오기, 구역, 추가 스폰 | 서버 `RaidSpawnApplier` |
| G2 | 특수 봇 무리(레이더·로그·컬티스트·블러드하운드): 켜기, 확률, 무리 크기 | 서버 |
| G3 | 레이드 보고에 역할별 사망 수 | 클라 `RaidContext`·보고, 웹 진단 |
| G4 | 스캐브 관리를 끈 맵(연구소 기본)에서 무한 방식 PMC 보충만 | 클라 `ScavDirector` |
| G5 | 웹: 특수 봇 페이지 적용, 보스 구역을 서버가 준 실제 구역 이름으로 고르기, 띠 문구 | 웹 |

**0.3에서 하지 않는 것**: 보스를 원래 없던 맵에 놓기·바닐라 보스 끄기(`noVanilla`)(0.4), 이벤트(할로윈 등, 0.4), 저격 스캐브·감염자 무리(0.4), 팩션(0.4), 장비(0.5), ORBIT 연동·프리셋(0.6). `scav.pscavChance`·`hotspotBoost`·`hotspotIgnoreCap`·`playerScavRemain`·`lateRaiders`·`near.useDefault`는 계속 "다음 판"입니다.

## 2. G1 보스 세부

서버가 레이드 맵 복제본의 `BossLocationSpawn` 중 웹 보스 목록(`BossRoleToId`)에 해당하는 항목을 고칩니다. 0.1처럼 새 값을 먼저 다 계산한 뒤 한 번에 씁니다(중간 예외 시 원본 유지).

| 웹 칸 | 게임 항목 | 규칙 |
|---|---|---|
| `chance` | `BossChance` | 0.1 그대로(공통 확률·즈랴치 예외 포함) |
| `followers=false` | `BossEscortAmount="0"` | 호위 없이 보스만 |
| `escMin~escMax` | `BossEscortAmount` | `"min,min+1,…,max"`(바닐라는 목록에서 하나를 고름). 둘 다 0이면 바닐라 값 유지 **[검토 필요]** |
| `tFrom~tTo`(분) | `Time` | 둘 다 0이면 바닐라 유지. 아니면 레이드마다 구간 안에서 초 단위로 하나 뽑음(시드 고정). 레이드 길이를 넘으면 길이의 90%로 자름 |
| `diff` | `BossDifficult`, `BossEscortDifficult` | `easy/normal/hard/impossible`. `random`이면 레이드마다 하나 뽑음. `normal`이 기본이지만 **웹 기본값을 그대로 두면 바닐라 유지**(사용자가 바꿨을 때만 적용)가 맞는지 **[검토 필요]** → 0.3은 "웹 값 적용" |
| `zones[map]` | `BossZone` | `['default']`이거나 비면 바닐라 유지. 아니면 그 맵의 **실제 보스 구역 이름**만 남겨 쉼표 목록으로(모르는 이름은 버림, 다 버려지면 바닐라). |
| `extra` | 항목 하나 더 | 같은 설정으로 복제 항목을 하나 더 넣어 한 번 더 굴림(확률 독립). 복제본 `SptId="gravity"` |

- 실제 보스 구역 목록: 서버가 시작 때 DB 맵의 보스 항목에서 `BossZone`을 모아 `MapInfo.BossZones`(맵별, 중복 제거)로 둡니다. 웹은 `api/meta`의 `maps[].bossZones`로 고릅니다.
- 웹이 예전 목업 구역 id(`dorms` 등)를 저장해 둔 경우: 실제 이름이 아니므로 버려지고 바닐라 구역을 씁니다(로그 한 번).

## 3. G2 특수 봇 무리

웹 `specials[id] = {on, chance, min, max}`. 대상 역할: 레이더 `pmcBot`, 로그 `exUsec`, 컬티스트 `sectantPriest`, 블러드하운드 `arenaFighterEvent`. 레이드 맵 복제본에서 해당 역할의 `BossLocationSpawn` 항목에:

- `on=false` → `BossChance=0`
- `chance` → `BossChance`(웹 기본값이 맵별 바닐라 값이라 그대로면 거의 같음)
- `min~max`(무리 전체 인원) → `BossEscortAmount = "(min-1),…,(max-1)"`(우두머리 1 + 호위). 컬티스트는 호위가 `sectantWarrior`로 따로 정해져 있어 같은 규칙.
- 저격 스캐브(`snipers`)·감염자는 0.4(웨이브·이벤트 쪽이라 다른 경로).

## 4. G3 보고에 사망 수

- 클라: `RaidContext.Killed[역할 키]`(`pmcUSEC`·`pmcBEAR`·`assault`(assaultGroup 포함)·`boss`·`other`). 봇 죽음은 `Player.OnPlayerDeadOrUnspawn`(게임 이벤트)으로 셉니다. 봇이 생길 때(`BotSpawner.OnBotCreated`) 구독합니다.
- `RaidReport`에 `Killed`를 더합니다(없으면 빈 사전 — 0.2 클라와 호환).
- 웹 진단 "계획 vs 실제"에 사망 수 열.
- 판정 18(스캐브 밀도)은 이 수치를 본 뒤 기본값을 조정합니다.

## 5. G4 연구소 무한 PMC 보충

`Scav.Managed=false`이지만 `Inf`가 있고 `RefillGroups`가 비어 있지 않으면, `NonWavesPatch`는 바닐라 스캐브 자동 스폰을 그대로 두고(true 반환) `ScavDirector.TickPmcOnly`로 PMC 차례만 돌립니다. 차례 간격·PMC 비율·맵 상한은 0.2 무한 방식과 같고, 스캐브 차례는 그냥 넘깁니다.

## 6. G5 웹

- `NOT_LIVE`에서 `specials` 제거. 특수 봇 페이지에 "저격 스캐브·감염자는 다음 판" 표시.
- 보스 페이지 구역 고르기: 서버 `maps[].bossZones`가 있으면 그 이름으로 버튼을 만들고, 없으면(서버 0.2 이하) 지금처럼.
- "지금 적용" 띠에 보스 호위·시간·난이도·구역, 특수 봇 추가. "다음 판"에서 뺌.

## 7. 시험

- 단위: `ApplyBosses`(호위 목록, followers 끔, 시간 구간·자르기, 난이도, 구역 거름·바닐라 유지, extra 복제), 특수 봇(끔·확률·크기), `MapCatalog` 보스 구역 수집, 보고 JSON `killed` 호환.
- 인게임: 세관 1판(레샬라 확률 100·호위 4·구역 하나로 바꿔 시작 직후 위치·호위 수 확인), 연구소 무한(PMC 보충 나오는지), 보고 사망 수.
