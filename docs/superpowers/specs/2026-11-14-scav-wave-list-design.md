# 스캐브 웨이브 목록 (PMC처럼 버블·드래그) 설계

날짜: 2026-11-14 · INBOX #43 · **사용자 승인 11-14**(1.0.6에 포함, "목록을 다른 맵에 복사" 버튼 채택, 구역 지정·MOAR 프리셋은 기각 — "Gravity 방식대로")

## 왜

Forge 사용자 피드백(MOAR 경험자): MOAR는 스캐브를 PMC와 똑같이 "웨이브 묶음 + 웨이브 사이 간격"으로 냈다. 그래서 시간대별로 스캐브 양을 퍼뜨리거나 조절하기 쉽고 직관적이다. Gravity·ABPS는 활동·휴식 창 동안 빈자리를 채우는 방식이라 "언제 몇 마리"가 눈에 안 보인다.

사용자(11-14): 스캐브도 PMC처럼 버블로 보이게, 버블을 클릭·드래그해 바꾸게, 확대 기능, 드래그 중 "언제 · 몇 마리" 표시. 방식은 **가안(직접 배치)** — 규칙으로 버블을 깔고, 그 뒤 버블 하나하나를 고친다. **지금 방식(채우기)도 쓰는 사람이 있으니 그대로 남긴다.**

## 목표 · 비목표 · 실패 조건

- 목표
  - 맵별 스캐브 방식에 **"웨이브 목록 (PMC처럼)"** 을 추가한다. 목록의 각 웨이브 = 시각 + 인원 범위.
  - 타임라인 스캐브 줄에 웨이브마다 버블(인원 숫자). 드래그로 시각 변경, 드래그 중 `12:30 · 3~5마리` 말풍선.
  - 버블 누르면 창: 시각·최소·최대·삭제. 웨이브 추가.
  - "PMC처럼 채우기" 생성기: 첫 웨이브·간격·인원·시간대 강도(기존 `scav.curve`)로 목록을 한 번에 깐다.
  - 타임라인 확대(1× · 2× · 4×), 가로 스크롤. 폰에서도 드래그.
- 비목표
  - PMC 버블 직접 배치(이번엔 스캐브만, 구조는 나중에 재사용 가능하게).
  - 기존 "채우기"·무한 보충·시작만 방식의 동작 변경.
- 실패 조건
  - 기존 설정(기본 `scavStyle=waves`) 사용자의 결과가 바뀜.
  - 목록 방식인데 웨이브 사이에 스캐브가 계속 채워짐(MOAR식이 아님).
  - 상한에 막힌 웨이브가 무한 대기·한꺼번에 몰림.

## 지금 구조 (조사)

- 스캐브 `scavStyle`: `waves`(웹 이름 "웨이브" — 실제로는 활동·휴식 창 + 소프트 캡까지 채우기), `infinite`, `start`.
- 클라 `ScavSchedule.Tick`(2초 틱)이 넣을 수를 내고 `ScavDirector`가 구역 가중치·거리·상한 예약을 지켜 1마리씩 `ActivateBotsByWave`.
- 서버 `SpawnPlanner.PlanScavs`는 시작 스캐브와 창 안 웨이브(게임 기본 `loc.Waves`)를 만든다. 게임 기본 웨이브는 쉼표 구역 목록을 못 읽는 문제가 기록돼 있다(시작 스캐브는 1명씩 쪼개 넣는 이유).
- PMC 버블도 규칙(첫 웨이브·간격·인원·강도·무작위 %)으로 판마다 계산한 결과이고 하나씩 옮길 수는 없다.

## 방법 (고른 것: 가 · 직접 배치)

| 안 | 내용 | 결과 |
|---|---|---|
| **가. 직접 배치** | 생성기로 버블을 깔고 하나씩 끌기·추가·삭제·인원 | **채택**(사용자 11-14). 끈 자리대로 나옴, 판마다 작은 흔들림만 |
| 나. 규칙만 | 버블을 끌면 규칙 값이 바뀜 | 버블 하나만 옮길 수 없어 요청과 안 맞음 |
| 다. 게임 기본 웨이브로만 | 서버가 `loc.Waves`에 목록을 넣고 클라는 관여 안 함 | 쉼표 구역·상한·거리 처리 문제로 탈락. 클라가 없을 때의 대체 경로로만 씀 |

## 설계

### 설정 (웹 state → 서버)

- `maps.<id>.scavStyle = "list"` (새 값). 기본은 그대로 `waves`.
- `maps.<id>.scavList = [{t, min, max}, ...]` — `t` 분(0~레이드 길이), `min`·`max` 0~20명. 최대 60개, 서버가 시각순 정렬·범위 자름.
- `maps.<id>.scavListJitter` — 판마다 각 웨이브 시각을 ± 이 초만큼 흔듦(0~120, 기본 20).
- 생성기 값(웹 전용 저장, 서버는 안 읽음): `maps.<id>.scavGen = {first, interval, min, max}`.
- 시작 스캐브(`scav.startOn` 등)·스캐브 하드 스톱·PMC 예약 자리·맵 상한은 지금처럼 적용한다. 목록 웨이브가 하드 스톱 뒤면 건너뜀.
- 시간대 강도(`scav.curve`)는 **생성기에서만** 인원에 곱한다(목록 인원이 곧 결과). 목록 방식에서 클라 소프트 캡 곡선은 쓰지 않는다.

### 서버

- `ConfigModel`: `scavStyle` 허용값에 `list`, `ScavList`(정렬·자름) 읽기.
- `SpawnPlanner`: `list`면 창 안 웨이브를 만들지 않는다(시작 스캐브만). 클라가 없을 때만 목록을 게임 기본 웨이브로 넣는다(구역 목록 문제는 시작 스캐브처럼 1명씩 쪼갬).
- `ClientSettingsBuilder`: `ScavDto`에 끝 칸 `ScavWaveDto[]? List`(시각 초·최소·최대)·`ListJitterSec`. **옛 클라 보호**: `list`일 때 `Style`은 `"start"`로 보낸다 → 옛 클라는 시작만(채우기 안 함), 새 클라는 `List`가 있으면 목록 방식.
- 판 시작 로그 한 줄: `스캐브 웨이브 목록 n개(총 a~b마리)`.

### 공용 (Gravity.Shared, 순수 로직 · 단위 테스트)

- `ScavWaveList`: 판 시작 때 시드로 각 웨이브의 실제 시각(± 흔들림)·인원(min~max 굴림)을 정한다.
  `Due(elapsed)` → 이번 틱에 낼 인원. 상한에 막히면 남은 인원을 그 웨이브에 들고 **최대 60초** 매 틱 재시도, 넘으면 버리고 버린 수를 센다. 반복은 목록 길이(≤60)로 끝남.
- `ScavSchedule`은 그대로(목록 방식에선 스캐브 채우기 차례를 쓰지 않음, PMC 무한 보충 차례는 지금처럼 독립 시계).

### 클라

- `ScavDirector`: `List`가 있으면 2초 틱마다 `ScavWaveList.Due`만큼 기존 스캐브 넣기 함수(구역 가중치·거리·예약)로 넣는다. 채우기는 끈다. 진단 로그(자세히): 웨이브 i 시각·낸 수·상한으로 버린 수.
- 새 반복문은 목록 길이·인원 상한으로 끝이 정해짐(2-5 규칙).

### 웹

- 스캐브 방식 칸: `waves` 이름을 "활동·휴식 채우기"로 바꾸고(값은 그대로), `list` "웨이브 목록 (PMC처럼)" 추가.
  처음 `list`를 고르면 목록이 비었을 때 생성기로 자동 채움.
- 타임라인 스캐브 줄(목록 방식): 웨이브마다 버블(지름 = 인원, 숫자 `3~5`), 편집 중엔
  - 드래그(마우스·터치 pointer 이벤트) → 시각 변경, 버블 위 말풍선 `12:30 · 3~5마리`, 놓으면 저장 바에 반영. 30초 단위 맞춤(확대 4×면 10초).
  - 탭 → 창: 시각·최소·최대·삭제, "여기 뒤에 웨이브 추가".
  - 줄 머리 → 생성기 창: 첫 웨이브·간격·인원·강도 미리보기 + "다시 채우기"(덮어쓰기 확인을 창 안에서).
- 다른 맵에 복사: 생성기 창의 "이 목록을 다른 맵에 복사" — 맵 고르기(여러 개) → 그 맵의 `scavStyle=list`·`scavList`·`scavListJitter`를 덮어씀. 레이드 길이가 짧은 맵은 길이 밖 웨이브를 버리고 몇 개 버렸는지 알림.
- 확대: 타임라인 위 `1× · 2× · 4×` 버튼(SVG 폭 배수, `.tl` 가로 스크롤), localStorage에 기억.
- 예상 인원·상한 팁(`estimate`·`capNeed`)이 목록 방식을 이해하게: 스캐브 총수 = 목록 합, 동시 목표 = 가장 큰 웨이브 + 시작 스캐브.

## 검증

- 단위: 설정 읽기(정렬·60개·범위·옛 설정 그대로), 기본값 = 1.0.5 결과, `ScavWaveList`(흔들림 범위·하드 스톱·60초 재시도·버림 수·시드 재현), DTO 옛 클라 보호(`Style=start`).
- 웹: 생성기 결과, 드래그 값(맞춤·범위), 창 추가·삭제, 확대 폭, 팁·예상 인원.
- 로컬(사용자): 클라 빌드, 세관 목록 방식 긴 판 — 로그의 웨이브별 시각·인원이 버블과 맞는지, 웨이브 사이에 스캐브가 안 채워지는지, 상한에 막힐 때 60초 안에 나오거나 버려지는지.
