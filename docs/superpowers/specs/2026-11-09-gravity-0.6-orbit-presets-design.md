# Gravity 0.6 ORBIT 연동·프리셋·진단·맵 변형 설계

> 원래 로드맵 0.6 = ORBIT·프리셋 JSON·진단(+ 0.1에서 미룬 맵 변형 구분). 참고 모드(ORBIT·Manimal·MapVariants)는 원리만 봤고 코드·데이터·문구는 가져오지 않았습니다.
> ORBIT 설정은 **읽기만** 합니다(파일을 고치지 않음).

## 1. 맵 변형(원본 / 변형)

- 변형 맵 = 같은 맵 id로 다른 배치를 싣는 모드: Manimal 교차로·등대·연구소 보일러, LennoxP90 FactoryClassic(공장 두 맵)·Interchange Rework. MapVariants는 판마다 원본/변형 중 하나를 `Location.Base`에 **참조째** 끼운다(kb 1.28, 서버 로드 중엔 변형이 걸려 있음).
- 판별: 서버 시작(PostLoad+1) 때 맵마다 `Base` 참조를 기억 → 레이드 때 지금 걸린 `Base`가 같은 객체면 "변형", 다르면 "원본". 변형 모드가 하나도 없는 맵은 늘 "원본".
- 적용: `maps.<id>.original`이 꺼진 원본 판, `maps.<id>.variant`가 꺼진 변형 판은 Gravity 스폰을 건너뜀(SPT·변형 모드 기본). 웹 기본값 그대로 등대 변형은 끔(Manimal 등대가 스폰 모드를 스스로 끄는 맵).
- **맵 정보는 판마다 지금 Base에서**: PMC 구역(BotPmc 지점 있는 구역)·스캐브 구역(Bot+Savage 지점 ∩ OpenZones, 없으면 웨이브 구역)을 그 Base로 계산(참조별로 한 번만). 원본을 고른 판에 변형 구역 이름을 넣으면 분대가 영원히 대기하기 때문(0.1의 구역 문제와 같은 원인).
- 웹: 맵별 설정 "원본 / 변형" 카드에 감지된 변형 모드 이름, 지난 판이 원본/변형 중 무엇이었는지 표시.

## 2. ORBIT 연동

- 서버 시작 때 `user/mods/<ORBIT 폴더>/config.json`을 읽어 웹에 보냄: 봇 재우기(ai_limiter.enabled)·잠드는/깨우는 거리·최소 깨어 있는 봇·PMC 탈출(loot.extract_pmc)·플레이어 스캐브 행동·팩션 장악(take_over_*)·바닐라 장악(vanilla_*). 판 표기는 ORBIT 서버 DLL 판.
- `orbit.nearAsGhost`(기본 끔): ORBIT이 있고 봇 재우기가 켜져 있으면 근처 보충 최소 거리 = max(설정값, max(잠드는, 깨우는 거리) + 10m), 최대 거리 = max(설정값, 최소 + 40m). 잠든 상태로 시작해 프레임을 아낌. 좁은 맵(공장·미궁)은 보정 안 함.
- `orbit.refillAfterExtract`(기본 켬): 클라가 봇 퇴장을 "사망"과 "탈출"로 나눠 셈(`BotDespawn`도 `BotDied`를 거쳐 0.5까지는 탈출이 사망으로 섞였음 — 살아 있으면 탈출). 무한 방식 맵에서 PMC가 탈출하면 같은 진영 1인 분대를 보충 목록 끝에 더함(판당 최대 20). 끄면 더하지 않음. 웨이브 방식은 상한 자리가 비는 것 말고는 변화 없음.
- `orbit.respectTakeover`(기본 켬): 켬 = ORBIT이 장악한 팩션도 스폰은 Gravity(행동만 ORBIT). 끔 = ORBIT이 장악한 팩션(take_over_ruaf·black_division)은 Gravity가 관리하지 않고 팩션 모드 기본 스폰에 맡김.
- 탈출 수는 레이드 보고(`Extracted`)와 웹 진단에 표시.

## 3. 프리셋(서버 저장)

- 0.5까지 내 프리셋(레이드·장비·스폰/맵)은 웹 메모리에만 있어 새로 고치면 사라졌다. `config/presets.json`에 저장(`api/library` GET/POST, 이 PC에서만 저장, 임시 파일 → 교체, 백업 5개).
- 웹은 프리셋을 만들기·복제·이름 바꾸기·삭제·가져오기 할 때 바로 서버에 저장(설정 "저장" 버튼과 별개).
- 전체 백업 파일(format `gravity-preset`) v3: 설정 + 내 프리셋 세 종류. v2 파일(장비 프리셋만)도 읽음.
- 장비 프리셋 "Gravity 자동 — 설치된 아이템으로 다시 만들기" = 서버가 아이템 가격 티어를 다시 계산(`api/gear/rebuild`, LiveFleaPrices처럼 가격이 바뀌는 모드용). 목업 예시 가져오기 버튼은 뺌.

## 4. 진단

- 감지 목록을 실제 값으로: ORBIT·SAIN·SVM·MapVariants·Manimal·FactoryClassic·팩션·Blackout·PPES·ABPS·APBS·Questing Bots(한눈에 칩, 호환 페이지 카드). 목업 시험용 "감지 상황" 스위치는 뺌.
- **Questing Bots가 있으면 스폰 모듈 잠금**(목업 문구대로, QB도 PMC를 스스로 스폰).
- 로그 수준 `diag.log`: off = 경고만, summary = 지금과 같음, verbose = 판마다 PMC 분대 목록·보스 결정까지. 클라도 같은 수준(설정에 실어 보냄).
- `diag.report`(기본 켬): 클라 보고를 받으면 계획과 함께 `config/reports/<시각>-<맵>.json`으로 저장(최근 20개).
- `diag.botLog`(기본 끔): 장비를 입힌 봇마다 역할·티어·레벨·주무기·방탄 등급을 `config/reports/gear-last.log`에 한 줄(판마다 새로, 최대 2000줄).
- 최근 경고: Gravity 경고·주요 알림 최근 30줄을 `api/meta.recent`로 보내 호환 페이지에 표시.
- 개발 페이지: "10번 굴리기" = 서버가 이 맵 DB 복제본에 지금 설정을 10번(다른 시드) 적용해 PMC·스캐브 계획 수와 나올 보스·특수 봇(확률 굴림)을 돌려줌(`api/dev/sim`). "웨이브 표 만들기" = 한 번 적용한 계획 JSON(`api/dev/plan`). 레이드 중 넣어 보기·게임 화면 표시(지점·구역·오버레이)는 클라 화면 작업이라 1.0.

## 6. 판정(검토 필요)

- 54. 변형 판별은 참조 비교 + 알려진 변형 모드 폴더 목록. 목록에 없는 새 변형 모드는 "원본"으로 보임.
- 55. 판마다 맵 정보를 지금 Base에서 다시 계산(참조별 캐시). 기준 인원(웹 MAPS 값)은 원본·변형 같음.
- 56. 탈출 = `BotSpawner.OnBotRemoved` 때 봇 플레이어가 살아 있음. 사망 수에서 뺌.
- 57. 탈출 보충은 무한 방식 PMC만, 1인 분대, 판당 20 상한. 기존 보충 목록보다 먼저 씀(별도 대기열).
- 58. `respectTakeover` 끔 = ORBIT이 장악한 팩션은 Gravity 관리 끔(웹 "Gravity가 관리"보다 우선).
- 59. Questing Bots 감지 = 스폰 모듈 잠금(ABPS와 같은 처리).
- 60. 시뮬레이션의 보스·특수 봇은 항목 확률만 굴림(바닐라 클라의 추가 조건 — 시간·트리거 — 은 안 봄).
- 61. 프리셋 저장소는 설정 파일과 따로(`presets.json`). 설정 백업 5개와 별도 백업 5개.
- 62. 변형 모드가 설치돼 있어도 서버 시작 때 스폰 지점 id가 SPT 원본 base.json과 같으면 그 맵은 원본으로 봄(Manimal 연구소 보일러가 이 경우).
- 63. 웹 맵별 구역 목록은 서버 시작 때 배치(변형 모드가 있으면 변형) 기준. 원본 판에는 그 판 배치의 구역을 쓰고, 웹에서 끈 구역 중 그 배치에 없는 이름은 무시(분대가 묶이지 않음). 배치별 구역 편집은 1.0.
- 64. ORBIT 맞추기 거리는 좁은 맵(공장·미궁)에 적용하지 않음.
- 65. 시뮬레이션의 "클라 있음"은 마지막 Hello가 판이 맞을 때. 실제 레이드라면 건너뛸 맵이면 이유를 같이 알림.
