# Gravity 0.3 나머지 설계: 시즌 이벤트·감염자·미룬 칸

> **상태: 초안, 사용자 미승인.** [검토 필요] = 1.0 때 한 번에 검토.
> **판 번호 바로잡기(사용자 11-09)**: 원래 로드맵 기준으로 0.3 = 보스 전체·특수 봇·시즌 이벤트·0.2에서 미룬 칸, 0.4 = 팩션 모드, 0.5 = 장비. 앞서 "0.3"·"0.4"라 부른 두 묶음(`2026-11-09-gravity-0.3-bosses-design.md`, `2026-11-09-gravity-0.4-design.md`)은 모두 원래 0.3의 앞부분입니다. 이 문서가 원래 0.3의 남은 부분이고, 끝나면 판 표기를 0.3.0으로 올립니다.

## 1. 범위

| 번호 | 기능 | 어디서 | 적용 시점 |
|---|---|---|---|
| R1 | 이벤트 켜고 끄기(할로윈·크리스마스·새해·만우절), 감지 사용, 소환·좀비·이벤트 장비·산타·선물·겨울 옷 | 서버 `EventControl`(SPT 이벤트 적용 직전) | **서버 재시작 후** |
| R2 | 이벤트 봇 확률: 감염자(맵마다 이번 판 감염 여부), 밤 컬티스트 의식, 산타 | 서버 레이드 복제본 | 판마다 |
| R3 | 플레이어 스캐브 이름 섞일 확률(`scav.pscavChance`) | 서버 SPT 봇 설정 | 판마다 |
| R4 | 스캐브 레이드 때 남는 PMC(`scav.playerScavRemain`) | 서버 계획 | 판마다 |
| R5 | 근처 보충 "기본 PMC/스캐브" 끄기(`near.useDefault`) | 공유 `NearSchedule` | 판마다 |
| R6 | 웹: 이벤트 담당(실제 감지값), 재시작 안내, 띠 문구 | 웹 | |

## 2. R1 이벤트 담당과 켜고 끄기

- SPT는 서버가 켜질 때 한 번(`GameCallbacks` 단계, `PostDbLoadService`) 날짜를 보고 이벤트를 DB 전체에 적용합니다. Gravity는 그 직전(`TypePriority = GameCallbacks - 1`)에 SPT 이벤트 설정(`SeasonalEventConfig`)만 고칩니다. DB를 직접 고치지 않습니다.
- 담당(`eventsOwner`): `gravity`면 Gravity가 고칩니다. `spt`면 손대지 않습니다. `svm`·`ppes`도 손대지 않습니다(그 모드가 담당). `auto`는 PastPresentEventSelector가 있으면 `ppes`, SVM이 있고 SVM 프리셋의 `Raids.RaidEvents`에서 `DisableEvents`·`Christmas`·`Halloween` 중 하나라도 켜져 있으면 `svm`, 둘 다 아니면 `gravity`입니다.
- Gravity 담당일 때:
  - `events.detect` 또는 `mode=on`인 이벤트가 하나라도 있으면 감지를 켭니다(`EnableSeasonalEventDetection`).
  - 이벤트마다 `mode=off`면 `Enabled=false`, `on`이면 `Enabled=true`에 날짜를 1/1~12/31로 둡니다. `auto`는 SPT 날짜 그대로입니다. 크리스마스는 SPT 항목 두 개(12월, 1월)에 같이 적용합니다.
  - 할로윈: `summon`이면 `EnableSummoning`. `zombies>0`이면 좀비 사용(`ZombieSettings.Enabled`). `gear`가 꺼지면 할로윈 이벤트 장비 표(`EventGear[Halloween]`)를 비웁니다.
  - 크리스마스: `santa>0`이면 산타 사용(`EnableSanta`). `gifts`는 크리스마스 은신처(`EnableChristmasHideout`), `snow`는 겨울 옷(`AdjustBotAppearances`)입니다. `gear`가 꺼지면 크리스마스 이벤트 장비 표를 비웁니다.
  - 새해·만우절: 켜고 끄기만 합니다(불꽃놀이·작은 봇 칸은 이벤트 자체와 같은 뜻).
- 판정 28: 두 이벤트를 동시에 "항상 켜기"하면 SPT가 이벤트를 차례로 적용하며 내부 표시를 마지막 것으로 덮어씁니다. 봇·맵 변경은 둘 다 들어갑니다. **[검토 필요]** 비용: 퀘스트 등 SPT의 "지금 할로윈인가" 판단이 하나만 참.
- ABPS 잠금이면 아무것도 하지 않습니다.

## 3. R2 판마다 이벤트 봇

이벤트가 실제로 켜져서 레이드 복제본에 이벤트 항목이 있을 때만 동작합니다. 담당이 누구든 적용합니다(웹 문구 "Gravity는 이벤트 봇 수·확률만").

- **감염자**: 맵 복제본의 `Events.Halloween2024.InfectionPercentage > 0`이면 이번 판 감염 확률을 굴립니다. 확률은 `specials.infected.on`이면 `specials.infected.chance[맵]`이고, 아니면 `events.halloween.zombies`입니다. 실패하면 감염 비율 0, 감염자 역할(`infected*`) 항목 확률 0으로 둡니다. 성공하면 SPT가 정한 감염 비율을 그대로 둡니다. 판정 29: 웹 "맵당 확률"을 "이번 판이 감염 판일 확률"로 읽습니다. 감염 정도(SPT가 맵마다 정함)는 바꾸지 않습니다. **[검토 필요]**
- **밤 컬티스트 의식**: `sectantPredvestnik` 항목 확률 = `events.halloween.nightCult`.
- **산타**: `gifter` 항목 확률 = `events.christmas.santa`.
- 특수 봇 페이지의 감염자 인원 칸은 적용하지 않습니다(SPT 감염자는 정해진 무리 구성과 감염 비율로 수가 정해짐). 웹에 안내합니다.

## 4. R3·R4·R5

- R3: 레이드를 적용할 때마다 SPT 봇 설정 `chanceAssaultScavHasPlayerScavName`을 `scav.pscavChance`로 둡니다(SPT 기본 10, 웹 기본 10).
- R4: `LocationLifecycleService.StartLocalRaid` 앞에서 세션별 진영(`PlayerSide`)을 기억합니다. `Savage`(스캐브 레이드)면 Gravity PMC 계획 무리 중 `playerScavRemain`%만 무작위로 남깁니다(시드 고정, 반올림). 시작 무리도 같은 비율입니다. 스캐브 쪽은 바닐라 SPT 스캐브 레이드 규칙을 따릅니다.
- R5: `NearDto`에 `UseDefault`(기본 true, 옛 서버와 호환)를 더합니다. `UseDefault=false`이고 직접 고르기가 켜져 있으면 모든 자리를 직접 고른 종류로 채우고, 두 종류 다 한도가 차면 그 자리는 비웁니다. 직접 고르기가 꺼져 있으면 `UseDefault=false`를 무시합니다(웹도 둘 다 끌 수 없게 안내).

## 5. 보류(판정 30)

- `hotspotBoost`(핫스팟 무리 +1명)·`hotspotIgnoreCap`(핫스팟은 상한 무시): 바닐라는 무리 인원과 봇 프로필을 구역 고르기 전에 정합니다(`BotBossSpawn.TrySpawn(…, followersCount, creationData)`). 핫스팟인지 알게 되는 시점에 인원을 바꾸려면 프로필을 따로 만들어야 하고, 상한 무시는 바닐라 상한 검사를 우회해야 합니다. 둘 다 스폰 실패 위험이 커서 1.0 이후로 미룹니다. 웹에 "아직 효과 없음"을 표시합니다. 비용: 고급 칸 두 개가 동작하지 않음.
- `scav.lateRaiders`: 웹에 칸이 없는 기본값이라 다루지 않습니다.

## 6. 시험

- 단위: 이벤트 설정 고치기(담당별·모드별·장비 끔), 감염 판 굴리기(0·100·특수 봇 우선), 밤 컬티스트·산타 확률, 남는 PMC 비율, 근처 보충 UseDefault.
- 인게임: 담당 `gravity`·할로윈 항상 켜기·공장 감염 확률 100 → 감염자 등장, 0 → 없음. 스캐브 레이드 1판(남는 PMC 비율 로그).
